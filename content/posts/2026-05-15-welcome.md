If you've ever stared at a few thousand lines of `rsyslog.conf` and `/etc/rsyslog.d/*.conf`
includes, trying to figure out **why** a particular log line ended up in a particular file —
this tool is for you. The same problem exists in syslog-ng, NXLog, Fluent Bit, Vector and
Logstash configurations; we start with rsyslog because that's where the pain is densest, but
the architecture is built for more dialects.

## The problem with log-pipeline configs

These tools are wonderfully flexible. They give you conditionals, lookup tables, dynamic
file paths, set/unset variables, and ruleset routing. But that flexibility also means a
config becomes a small program. And like any program, it can become hard to predict by
reading alone.

The usual debugging tools — restarting the daemon, watching `tail -f`, throwing in extra
output actions — are slow, invasive, and don't tell you **which** rule fired, only what came
out the other end.

## What this tool does

logflow-sim parses your configuration in-process (no shelling out, no fixtures), builds a
normalized, vendor-neutral intermediate representation, and then runs your test messages
through a deterministic evaluator that emits a trace:

- which input matched the transport/port,
- which ruleset was chosen,
- every condition that was evaluated and its result,
- every lookup hit and miss,
- every variable that was set, reset, or unset,
- every action that fired, with the resolved DynaFile path or omfwd target.

Each trace event carries a **source location** — the file, line, and column in your config
that produced it. Click through to the exact line.

## What it isn't

This is not a full re-implementation of any of these tools. It does not run queues, write
files, send packets, or replicate every quirk of the upstream parser. It is an **explainer**
— built so you can answer "what will my pipeline do with this message?" without spinning up
a container, generating traffic, and reading the disk.

Unknown statements aren't silently skipped — they're preserved with a diagnostic. Silent
skipping is a correctness bug.

## Roadmap

- **Today**: rsyslog / RainerScript — including lookup tables, regex extract, system
  variables, all the templating modifiers we've found in real configs.
- **Next**: syslog-ng. Source/filter/destination/log paradigm fits the same normalized IR.
- **After**: NXLog, Fluent Bit / Fluentd, Vector, Logstash — in order of community pull.

If your config breaks the parser, open an issue. The corpus of real configs is what makes
the tool robust.
